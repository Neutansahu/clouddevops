Build · Test · Deploy

⚡ CI/CD Pipeline

Every push to main is tested, built into a Docker image, stored in Amazon ECR and deployed to EC2 through Systems Manager. Run a simulation below.

    Press “Run pipeline” to watch a deployment.

    Technologies

    Managed AWS services and open tools, wired together with short-lived credentials.

    Node.js

    Express app with a /health endpoint on port 8000.

    Docker

    Multi-stage image that runs as a non-root user.

    GitHub Actions

    Test, build and deploy on every push, with OIDC sign-in to AWS.

    Amazon ECR

    Private registry with scan on push and tags set to the commit SHA.

    Amazon EC2

    Docker host for staging and production, tagged by environment.

    Systems Manager

    Run Command deploys and Session Manager shells, with no SSH port open.

    IAM

    Separate build and deploy roles, scoped to this repository.

    CloudWatch

    Container logs, CPU alarms and notifications through SNS.

    Features

    What the pipeline gives you out of the box.

    Automated tests

    A failing test stops the pipeline before anything is built.

    Secure access

    No stored AWS keys and no SSH. GitHub signs in with OIDC and servers are reached through Systems Manager.

    Staging first

    Production only accepts images that already ran on staging.

    One-click rollback

    Return to the previous image in under two minutes.

    Health-checked deploys

    A deploy only counts when /health answers. Otherwise the old container comes back.

    Image scanning

    Critical, high and medium findings show next to every image.

    Audit trail

    Every sign-in, deploy and rollback is logged with who did it and when.

    Secrets stay out of images

    Runtime secrets live on the server, never in GitHub or the Docker image.

    One deploy at a time

    A lock per environment stops two releases from colliding.

    Deployment dashboard

    Track environments, runs and images, then deploy or roll back.
